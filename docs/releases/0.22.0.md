# Danvas 0.22.0 release evidence

Released September 5, 2026. This release adds optional trusted-profile credential commands while leaving secret storage and provider authentication external. Existing explicit environment/file inputs remain supported; offline diagnostics do not execute the helper. See [Authentication](../authentication.md) for the supported contract and [Compatibility](../compatibility.md) for rollback requirements.

## Verification

- Final local suite: 1,102 passed; branch-aware coverage 85.76%, above the 82% gate. Ruff, ty, documentation checks, distribution checks, and isolated editable/wheel installation checks passed.
- [Exact-candidate branch CI](https://github.com/olearydj/danvas/actions/runs/33993745421) and [signed-tag CI](https://github.com/olearydj/danvas/actions/runs/33993941666) passed Python 3.12–3.14, macOS, dependency auditing, secret scanning, and installation gates.
- Anonymous installation from the exact `v0.22.0` tag passed.
- After the PyPI upgrade, the global command reported 0.22.0. Offline auth doctor selected a command with status `not_requested`; a bounded installed live current-user diagnostic reached Canvas. No token or user identity was printed by the live verification harness.

Two issues were corrected before tagging: help tests inherited `TERM=dumb`, and the security-policy test retained an old version assertion. Final review also tightened helper newline validation to reject a bare carriage return. The final checks above include those corrections.

The packaged skill retains its existing `compatibility` metadata. The generic system skill validator rejected that field; Danvas’s own packaged-skill contract and isolated installation checks passed. This is a validator-schema mismatch, not a claim that the generic validator passed.

## Scope

No shared helper package or credential store was added. Cross-invocation prompt reuse is governed by the external provider/session policy; this release does not establish a prompt-frequency guarantee. Personal profile references and launcher migration details belong in local configuration and personal tooling documentation, not the public application skill.
