# Migrating To 0.21.0: Classic Quiz Analysis Export

Version `0.21.0` adds one supported acquisition command for Canvas Classic Quiz
student-analysis reports. Existing `quiz analysis` and `quiz import-qti`
syntax and behavior are unchanged.

## New Export Workflow

Plan the report request, apply it only after authorization, then inspect the
verified private CSV locally:

```bash
danvas quiz export-analysis --course-id 101 --quiz-id 202
danvas quiz export-analysis --course-id 101 --quiz-id 202 --apply
danvas quiz analysis \
  .danvas/private/quizzes/quiz-202/student-analysis.csv
```

The first command may perform bounded Canvas reads but never requests or
downloads a report. The second uses Canvas's create-or-reuse report endpoint,
polls its bounded progress, reads back stable report/file identity, validates
the CSV, and commits it privately.

Report generation is a Canvas mutation because the endpoint is a `POST`. This
classification applies even though the operation changes no quiz content,
grade, publication state, or notification.

## Private Output And Evidence

Initialized projects default to:

```text
.danvas/private/quizzes/quiz-202/student-analysis.csv
```

The CSV and SHA-256 integrity sidecar use the existing private-artifact
contract: `0700` directories, `0600` files, no permissive temporary window,
no-clobber by default, and detectable sidecar-last consistency. `--overwrite`
is explicit. Outside a project, `--output` is required before authentication.

Terminal and retained transaction evidence contain aggregate state, bounded
artifact paths, and stable course/quiz/report/progress/file IDs. They do not
retain protected URLs, raw Canvas responses, student rows, names, login IDs,
answers, scores, question text, or Canvas file names.

## Report Scope And Supported Types

The default request covers the current Classic Quiz version. Add
`--includes-all-versions` only when required; current and all-version reports
are distinct identities during reconciliation.

The acquisition command supports Classic Quizzes and identified Surveys.
Anonymous Surveys are rejected before the report request because their CSV may
omit the required stable `id` and `submitted` columns. Previously downloaded
anonymous Survey CSVs remain usable with local `quiz analysis` when its parser
can interpret them.

New Quizzes are not supported. Their report service and response shape are
different, and `0.21.0` does not add a compatibility adapter.

## Uncertain Outcomes And Automation

Applied report creation is attempted exactly once. Danvas reconciles a `409`
only when one exact in-progress report exists. An exception after possible
acceptance never triggers an automatic retry.

Exit zero means either a valid plan or `applied_verified`. These states exit
nonzero and require review:

- `accepted_unverified`: Canvas may have accepted the request, but danvas could
  not bind and verify one exact result;
- `conflict`: report identity was absent or ambiguous;
- failed, unknown, or timed-out progress;
- invalid, oversized, or failed CSV download; and
- private output collision or unsafe destination.

Automation must inspect the retained status and safe next action rather than
blindly rerunning `--apply` after a nonzero result.

## Direct Scripts And Browser Workflows

Direct report-endpoint scripts should migrate to `quiz export-analysis` so the
request participates in danvas's plan/apply, origin, privacy, reconciliation,
and evidence contracts. Missing command coverage does not itself authorize a
direct API, browser, or provider-specific fallback.

Manual browser-downloaded Classic Quiz CSVs remain compatible with:

```bash
danvas quiz analysis PATH/TO/student-analysis.csv
```

## Upgrade And Rollback

After the signed release is available, install the exact tag and verify it
outside a source checkout:

```bash
uv tool install --force \
  "danvas-cli @ git+https://github.com/olearydj/danvas.git@v0.21.0"
danvas --version
danvas auth doctor
danvas quiz export-analysis --help
```

To roll back the executable, reinstall exact tag `v0.20.0`. Private CSV pairs
created by `0.21.0` remain ordinary protected files and can still be consumed by
`0.20.0`'s local `quiz analysis` command.
