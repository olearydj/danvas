# Migrating To 0.20.0: Agent Interface

Version `0.20.0` makes the installed `danvas` CLI a richer authority for people
and software agents. It adds progressive help, packaged offline task guides,
versioned command description, and a portable Agent Skill with a bounded local
installer.

Canvas requests, course configuration, credential delivery, mutation guards,
private artifacts, and evidence schemas are unchanged from `0.19.0`.

## Help Is Longer By Design

Root help now explains the global safety and privacy model. Command-family help
adds common workflows and identity rules. Leaf help names effects, retained
output, plan/apply behavior, verification, and safe recovery.

Do not parse Rich help as a machine API. Exact whitespace, wrapping, borders,
and prose may evolve. Use the versioned description instead:

```bash
danvas describe --format json
danvas describe assignments update --format json
```

The JSON schema is `danvas-command-guide-v1`. Executable parameters come from
Typer/Click, effects come from the access registry, privacy comes from the
artifact registry, and workflow semantics come from the command-guide registry.

## Offline Task Guides

List and read packaged guides without a project, credential, or network:

```bash
danvas guide list
danvas guide setup
danvas guide safety
danvas guide grades
danvas guide agents
```

Guides provide task sequences; leaf help remains the authority for the exact
installed option surface.

## Portable Danvas Skill

The `danvas-cli` Python distribution now contains one generic Agent Skill named
`danvas`. The distribution, command/import package, and skill names remain
distinct:

- distribution: `danvas-cli`;
- executable and import package: `danvas`; and
- Agent Skill: `danvas`.

Inspect the version-matched files and hashes without writing:

```bash
danvas skill show
```

The public skill contains no executable scripts, broad tool grant, password
manager integration, institution defaults, personal workspace policy, or Canvas
credential. It points agents back to installed help, guides, and description for
current command truth.

## Explicit Skill Installation

Installation requires an agent target. User scope is the default; project scope
requires an explicit root:

```bash
danvas skill install --agent shared --dry-run
danvas skill install --agent shared
danvas skill install \
  --agent claude-code --scope project --project-root /path/to/project --dry-run
```

Initial target roots are:

| Agent | User scope | Project scope |
| --- | --- | --- |
| `shared` | `~/.agents/skills/danvas` | `.agents/skills/danvas` |
| `codex` | `~/.agents/skills/danvas` | `.agents/skills/danvas` |
| `claude-code` | `~/.claude/skills/danvas` | `.claude/skills/danvas` |
| `gemini` | `~/.gemini/skills/danvas` | `.gemini/skills/danvas` |
| `copilot` | `~/.copilot/skills/danvas` | `.github/skills/danvas` |

`shared` intentionally uses the portable `.agents/skills` path understood by
multiple hosts. A vendor target writes only its named vendor path.

The installer classifies before writing:

- `absent`: atomically create the complete directory;
- `exact`: make no change;
- `owned_stale`: atomically update only when installed content still matches
  danvas provenance and hashes;
- `owned_modified`: refuse because local content differs;
- `unowned`: refuse because another person or tool may own the target; and
- `unsafe`: refuse symlinks, non-directory parents, path escapes, or unsafe
  content.

There is no `--force`, `--update`, or `--apply` escape hatch. The install verb is
local-write intent; `--dry-run` writes nothing. Danvas never edits agent settings,
trust policy, shell configuration, marketplaces, or unrelated skills.

## Diagnose Discovery Offline

`skill doctor` checks the `danvas` executable and every allowlisted user/project
location by default. Narrow it only when useful:

```bash
danvas skill doctor
danvas skill doctor --agent gemini --project-root /path/to/project
```

Doctor reports absent, exact, stale, modified, unowned, unsafe, and executable
version states with bounded repair commands. It performs no agent login, remote
fetch, Canvas request, or credential resolution.

## Personal Skills Remain Separate

Installing the generic `danvas` skill does not replace a private teaching or
organization overlay. Keep institution paths, local filing conventions,
approval policy, and other personal instructions in their existing scoped
configuration. A separately authorized cleanup may reduce that overlay after
the public skill is released and behavior-tested.

## Upgrade And Rollback

After the signed tag is available, replace the installed tool with the exact
release and verify it outside a source checkout:

```bash
uv tool install --force \
  "danvas-cli @ git+https://github.com/olearydj/danvas.git@v0.20.0"
danvas --version
danvas auth doctor
danvas skill show
```

To roll back the executable, reinstall exact tag `v0.19.0`. A skill already
installed by `0.20.0` remains an ordinary local directory; `0.19.0` does not
manage it. Inspect and move or remove that directory manually only if the host
must stop discovering it.
