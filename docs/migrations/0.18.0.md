# Migrating To 0.18.0: Public Beta Boundary

Version `0.18.0` completes the four-release public-readiness program. It changes
the Python distribution name, makes new project source discovery explicit,
generalizes gradebook and Panopto configuration, removes two due aliases, and
declares the supported Python/OS boundary.

Read this guide before replacing a `0.17.x` uv tool installation.

## Distribution Name Changed

The old Python distribution was named `danvas`. The new distribution is
`danvas-cli`; both install a command named `danvas`. Do not use `--force` to
install one over a tool environment owned by the other distribution.

Inspect the existing tool first:

```bash
uv tool list
command -v danvas
danvas --version
```

Remove the old distribution, then install the exact new tag anonymously:

```bash
uv tool uninstall danvas
uv tool install \
  "danvas-cli @ git+https://github.com/olearydj/danvas.git@v0.18.0"
```

Verify distribution ownership, executable resolution, and runtime version:

```bash
uv tool list
command -v danvas
danvas --version
danvas --help
danvas auth doctor
```

`uv tool list` must show `danvas-cli v0.18.0` and no separate `danvas`
distribution. `danvas --version` must report `danvas 0.18.0` outside a source
checkout.

If the uninstall step is skipped, uv may refuse the install or leave two tool
environments claiming the same executable. A successful exit alone is not
proof of a successful migration; inspect both `uv tool list` and the resolved
executable.

To roll back the tool installation without changing course files:

```bash
uv tool uninstall danvas-cli
uv tool install \
  "danvas @ git+https://github.com/olearydj/danvas.git@v0.17.0"
uv tool list
danvas --version
```

The import package remains `danvas`, so Python code must not change imports
merely because the distribution was renamed.

## New Projects Use `standard-v1`

A new initialization now writes the complete effective source layout:

```bash
danvas init 101 --profile example-university
```

The default `standard-v1` layout discovers:

```text
content/assignments/*.md
content/announcements/*.md
content/discussions/*.md
content/quizzes/*.md
content/pages/*.md
content/pages/*.html
```

It excludes Page preview HTML and records output directories for announcements,
discussions, and Pages. Init writes configuration only; it does not create,
move, or rename authored files.

Choose the historical layout explicitly when creating a project that needs the
case/chapter convention:

```bash
danvas init 101 --source-layout legacy-v1
```

## Existing Projects Stay Legacy Unless Configured

An existing initialized project without `[sources]` keeps the exact `0.17.0`
implicit `legacy-v1` behavior:

```text
content/cases/*-assignment.md
content/quizzes/chap*.md
```

No layout is inferred from repository contents. `init --force` preserves the
existing effective source configuration unless `--source-layout` is explicit:

```bash
# Preserve the existing effective layout.
danvas init 101 --force

# Deliberately materialize the standard layout instead.
danvas init 101 --force --source-layout standard-v1
```

Changing layouts does not move sources. Move files only as a separately
reviewed repository change after confirming the new include patterns.

Custom include patterns remain supported. If announcement, discussion, or Page
patterns do not share one unambiguous static parent, configure `output_dir` so
status and sync know where missing local sources belong.

```toml
[sources.announcements]
include = ["materials/news/*.md", "archive/news/*.md"]
output_dir = "materials/news"
```

Status suggestions and omitted sync destinations now use this effective
configuration rather than fixed `content/...` paths.

## File Inventory Ignores Can Be Replaced

Omitting file-inventory configuration preserves the old convenience ignores.
Custom patterns extend them by default:

```toml
[files.inventory]
ignore = ["scratch/**"]
```

To include conventional directories such as `grading/`, `_archive/`, and
`_inventory/`, disable the convenience set:

```toml
[files.inventory]
use_default_ignores = false
ignore = ["scratch/**"]
```

`.git/`, `.danvas/`, and an active inventory output directory remain mandatory
exclusions. Reports record the effective policy.

## Gradebook Heading Aliases

English Canvas gradebook headings remain the built-in profile. A known export
using other exact headings can define role aliases in `course.yaml`:

```yaml
gradebook_heading_aliases:
  student: [Étudiant]
  id: [Identifiant]
  points_possible: [Points possibles]
  unposted_final_score: [Note finale non publiée]
```

Aliases extend the English profile and are not locale detection. One alias
cannot belong to multiple roles. Multiple observed headings for a required
single role are rejected as ambiguous. Diagnostics name the role, configured
aliases, and a bounded heading list without student rows.

## Panopto Configuration And Interrupted Bundles

Experimental Panopto selection can now be pinned in project configuration:

```toml
[integrations.panopto]
caption_language = "English_USA"
tool_id = 202
base_url = "https://media.example.edu/"
```

CLI selectors override project configuration. Configure either `tool_name` or
`tool_id`, not both.

Caption retry no longer creates implicit `-2` or `-3` filenames. Without
`artifact-manifest.json`, danvas inventories existing caption/sidecar pairs:

- valid requested session pairs are reused by session ID and SHA-256;
- missing, tampered, duplicate, cross-session, or unexpected pairs block; and
- newly downloaded pairs use deterministic names.

Do not delete an incomplete bundle merely to make a retry proceed. Preserve it,
follow the move-aside guidance, and reconcile whether it contains the only copy
of protected captions or evidence from an interrupted run.

## Removed Options

These old spellings are now unknown options and fail during parsing before
project, output, credential, or network work:

```bash
# Removed
danvas assignments overrides-sync assignment.md --live --confirm apply

# Current
danvas assignments overrides-sync assignment.md --apply --confirm apply
```

```bash
# Removed
danvas discussions score DISCUSSION_URL 2 1 1 5 --upload

# Current: create a private plan, review it, then use the grade transaction.
danvas discussions score DISCUSSION_URL 2 1 1 5
danvas grades post .danvas/private/discussions/topic-202/grade-plan.csv
danvas grades post \
  .danvas/private/discussions/topic-202/grade-plan.csv --apply
```

`DISCUSSION_URL` must be the actual Canvas discussion URL; `topic-202` is the
placeholder path corresponding to topic ID `202`.

## Roster Compatibility

The default roster header remains `LoginID`. `--schema legacy-v1` still emits
the deprecated `Email` label in `0.18.0`, now with a fixed warning that the
option is removed in `0.19.0`.

Update downstream readers now. Danvas's internal reader accepts both headers
during this release but rejects an input containing both.

## Timezone Validation

An invalid explicit `danvas init --timezone` now fails before profile secret
resolution, Canvas access, or project writes. Canvas/profile fallback ordering
is unchanged.

## Supported Runtime

The declared range is now:

```text
Python >=3.12,<3.15
Linux or macOS
```

Windows is unsupported because danvas cannot promise its POSIX private-file
permission and symlink boundary there. Python 3.15 is intentionally outside the
range until tested and reviewed.

## Public Documentation

README is now a concise entry point. The public authority chain is the README,
command help, and the guides for configuration, authentication, privacy,
compatibility, authored sources, mutation safety, contribution, and security.
The internal backlog and sprint notes are design history and are not required
for ordinary installation or use.
