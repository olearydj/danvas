# Migrating To 0.15.0: Canvas Instance Profiles

Version 0.15.0 removes danvas's built-in institutional host and timezone. It
adds named, non-secret Canvas profiles while preserving initialized projects
and existing environment/secret-provider workflows.

## Who Must Change Configuration

Existing course projects whose `.danvas/config.toml` contains `canvas.api_url`
continue to select the same Canvas instance. Existing project timezones also
continue to drive date-only authored fields.

You must configure an instance if you previously ran Canvas-backed commands
outside an initialized project without `--api-url` or `CANVAS_API_URL`. Such a
command now stops before secret resolution with setup guidance; it never falls
back to another institution.

## Recommended: Add A User Profile

Create `danvas/config.toml` under your operating system's standard user config
directory. Typical locations are:

- macOS: `~/Library/Application Support/danvas/config.toml`
- Linux: `${XDG_CONFIG_HOME:-~/.config}/danvas/config.toml`

Use non-secret references only:

```toml
default_profile = "example-university"

[profiles.example-university]
api_url = "https://canvas.example.edu/"
timezone = "America/New_York"
secret_name = "canvas-example-university"
secret_provider = "auto"
op_reference = "op://Education/Canvas/credential"
api_key_env = "CANVAS_EXAMPLE_UNIVERSITY_API_KEY"
```

Do not put an API key, token, or credential value in this file. Danvas rejects
known raw-secret fields in profiles.

Initialize a project with the profile:

```bash
danvas init 101 --profile example-university
```

The selected profile and resolved API URL are recorded as stable project
configuration. The token remains in the configured provider.

## Compatibility Alternatives

One-off explicit configuration still works:

```bash
danvas courses --api-url https://canvas.example.edu/
```

The existing environment fallback also remains supported:

```bash
export CANVAS_API_URL=https://canvas.example.edu/
export CANVAS_API_KEY=replace-with-your-token
danvas courses
```

The fixed `secretpath` name `canvas` remains the default when no profile or
`--secret-name` selects another name. Existing `CANVAS_SECRET_PROVIDER`,
`CANVAS_API_KEY_OP_REFERENCE`, `CANVAS_API_KEY_ENV`, and `CANVAS_API_KEY`
workflows continue to resolve after the instance is known.

## Precedence

Profile selection is:

1. `--profile`
2. `[canvas].profile` in `.danvas/config.toml`
3. `DANVAS_PROFILE`
4. user `default_profile`

Canvas API URL selection is separate:

1. `--api-url`
2. `[canvas].api_url` in `.danvas/config.toml`
3. the selected profile's `api_url`
4. `CANVAS_API_URL`

This means a shell-level `CANVAS_API_URL` cannot redirect an initialized
project whose API URL is pinned.

Credential-reference precedence is explicit CLI options, then selected-profile
references, then the existing environment fallbacks. Token values do not choose
the Canvas host.

## Timezones During Init

`danvas init` no longer defaults to `America/Chicago` or any other timezone.
Resolution is:

1. explicit `--timezone`
2. recognized Canvas course timezone metadata
3. selected-profile `timezone`
4. unconfigured

Canvas may return Rails-style timezone labels. Danvas maps a small explicit set,
including `Central Time (US & Canada)`, to IANA names. It reports an unknown
label and never guesses from the institution, system timezone, or locale.

When no timezone resolves, initialization succeeds but omits
`[canvas].timezone`. Date-only assignment fields then fail with the existing
actionable message until you add an IANA timezone or use explicit offset-aware
`*_at` values.

## Offline Diagnostics

This remains valid outside a project with no profile or API URL:

```bash
danvas auth doctor
```

It reports `API URL: unconfigured` and continues provider diagnostics. A live
check requires an instance:

```bash
danvas auth doctor --profile example-university --check-canvas
```
